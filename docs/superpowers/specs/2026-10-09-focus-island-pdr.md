# Focus Island — PDR (Product Design Requirements)

- Дата: 2026-10-09
- Статус: черновик на ревью (ревизия 2: план дня заменён канбан-доской)
- Основа: форк [open-vibe-island](https://github.com/Octane0411/open-vibe-island) (GPL v3), локальная копия в `upstream/`

## 1. Проблема

Пока Claude Code выполняет задачу (1–10 минут), у пользователя нет понятного следующего шага. Пауза заполняется думскроллингом, контекст теряется, по возвращении к сессии нужно заново вспоминать, что происходило. Дополнительно: сессии Claude теряются — через день уже непонятно, какая сессия про что и как в неё вернуться.

## 2. Цель продукта

1. Превратить каждое ожидание Claude в осмысленное действие — следующую задачу с канбан-доски или ждущую сессию.
2. Вести задачи на простой канбан-доске (как Trello) и связывать с ними сессии Claude.
3. Никогда не терять сессии Claude: полная история с возможностью вернуться в любую.

Не-цели: полноценный таск-трекер (метки, дедлайны, команды), тайм-трекинг для отчётности, блокировка сайтов, поддержка агентов кроме Claude Code.

## 3. Пользователь

Один разработчик (личный инструмент), macOS 14+, работает в нескольких параллельных сессиях Claude Code в терминале (iTerm/Ghostty/Terminal/tmux/Warp). Распространение не планируется — GPL v3 не ограничивает.

## 4. Ключевые сценарии

**S1. Завести задачу.** Пользователь открывает доску (окно Board из island или глобальный хоткей) либо жмёт «+» в раскрытом island → вводит заголовок, опционально описание и проект → задача попадает в ту колонку, где её создали (quick-add из island — в Todo). Задачи перетаскиваются между колонками и внутри колонки.

**S2. Старт сессии.** Пользователь запускает `claude` в терминале → в island появляется сессия и ненавязчивый чип «Привязать к задаче?» с задачами из Todo / In progress (сначала — задачи того же проекта, что `cwd`) + «Новая задача» + «Пропустить». Сессия запускается без ожидания — привязка асинхронна.

**S3. Claude ушёл в работу.** Пользователь отправил промпт, Claude начал вызывать инструменты. Через 15 с (настраивается) island раскрывается с одной карточкой «Что дальше?» по правилам (см. F5). Пользователь жмёт действие — island переключает в терминал нужной сессии / берёт следующую задачу из Todo / открывает поле заметки.

**S4. Отвлечение.** Хотя бы одна сессия в работе, а пользователь 20 с (настраивается) находится в приложении/на сайте из стоп-листа → island мягко раскрывается: текущая задача + ждущие сессии + следующая задача из Todo + кнопка «Вернуться». Без блокировок, без звука по умолчанию.

**S5. Возврат к старой сессии.** История (или детали задачи) → поиск по проекту/тексту → «Resume» → открывается новое окно терминала с `cd <cwd> && claude --resume <session_id>`.

**S6. Задача готова.** Пользователь перетаскивает карточку в Done (или жмёт «Готово» в island). В деталях задачи видны все привязанные сессии с Resume/Jump.

## 5. Функциональные требования

### F1. Island с живыми сессиями (наследуется из апстрима)
- Список живых сессий Claude, фазы `running / waitingForApproval / waitingForAnswer / completed`.
- Карточки PermissionRequest / AskUserQuestion / ExitPlanMode с ответом из island.
- Jump-to-terminal (`TerminalJumpService`).
- Установка хуков в `~/.claude/settings.json` (`ClaudeHookInstaller`).

### F2. История сессий
- Постоянное хранилище всех сессий Claude, без TTL.
- Поля записи: `sessionId`, `cwd`, `projectName` (последний компонент `cwd` или имя git-репо), `title`, `firstPrompt`, `lastPrompt`, `lastAssistantMessage` (обрезано до 500 символов), `startedAt`, `lastActivityAt`, `endedAt?`, `status` (`live` / `ended`), `taskId?`, `transcriptPath`.
- Источники: живые хуки (upsert при каждом событии) + первичный backfill всех `~/.claude/projects/**/*.jsonl` при первом запуске, далее — инкрементально по mtime файлов при старте приложения.
- UI: вкладка «История» в окне доски (полная: группировка по дням, фильтр по проекту, полнотекстовый поиск по title/prompts) и последние 10 сессий в раскрытом island.
- Resume: открывает новое окно в терминале по умолчанию (настройка: Terminal / iTerm / Ghostty) с `cd '<cwd>' && claude --resume <sessionId>`. Если сессия ещё живая — вместо Resume показывается Jump.
- Если `cwd` больше не существует — Resume недоступен, показывается подсказка.

### F3. Канбан-доска
- Одна доска, фиксированные колонки: **Backlog → Todo → In progress → Done**.
- `Task`: `id`, `title` (обязателен), `description?` (plain text), `column`, `position` (порядок в колонке), `projectPath?` (папка проекта: выбирается из известных `cwd` истории или вручную), `note?`, `createdAt`, `updatedAt`, `doneAt?`.
- Окно доски `BoardWindow` (обычное NSWindow со SwiftUI) открывается кнопкой из раскрытого island и глобальным хоткеем (по умолчанию ⌥⌘B):
  - колонки с карточками, drag & drop между колонками и внутри колонки;
  - карточка: заголовок, тег проекта, бейдж числа привязанных сессий, индикатор «есть живая сессия»;
  - детали задачи (sheet): заголовок, описание, проект, заметка, список привязанных сессий с Resume/Jump, удаление;
  - фильтр по проекту, inline-добавление задачи внизу каждой колонки;
  - Done показывает задачи за последние 7 дней, остальные — по кнопке «Архив».
- В island:
  - свёрнутый: заголовок текущей задачи (задача последней активной привязанной сессии, иначе первая в In progress), обрезка по ширине нотча;
  - раскрытый: вкладка «Задачи» — компактный список In progress + Todo, quick-add «+» (в Todo), «Готово» по задаче, кнопка «Открыть доску».

### F4. Привязка сессии к задаче
- На `SessionStart` (source `startup`) в карточке новой сессии появляется чип: задачи из In progress и Todo (задачи, у которых `projectPath` совпадает с `cwd` или является его родителем, — первыми), «Новая задача…» и «Пропустить».
- Выбор задачи: `taskId` пишется в запись истории сессии; если задача в Backlog/Todo — она автоматически переезжает в In progress.
- «Новая задача…»: задача создаётся в In progress с заголовком из первого промпта сессии (обрезка до 80 символов, редактируемо; до первого промпта — заголовок = `projectName`), `projectPath = cwd`.
- Для `source=resume` привязка наследуется из истории без вопроса.
- Одна сессия — максимум одна задача; у задачи может быть много сессий. Привязку можно поменять из карточки сессии, истории или деталей задачи.
- Завершение сессии задачу не двигает — в Done переводит только пользователь.

### F5. «Что дальше?» (NextActionEngine, без LLM)
Триггер: сессия перешла в «работу» — фаза сменилась на `running` (в апстриме и `UserPromptSubmit`, и `PreToolUse` дают `activityUpdated(phase: .running)`) либо при `running` сменился `lastUserPrompt` — и через `nextActionDelay` (по умолчанию 15 с) сессия всё ещё в `running`. Не чаще одного раза на ход (turn) сессии. Не показывать, если пользователь уже дольше 60 с работает в другом не-стоп-листовом приложении (значит, он чем-то занят).

Приоритет карточки (первое подходящее):
1. **Ждущая сессия**: другая сессия в `waitingForApproval` / `waitingForAnswer`, либо `completed` и пользователь её ещё не открыл после завершения. Действие: «Перейти» (jump) / ответ прямо из карточки для permission.
2. **Следующая задача**: первая по `position` задача из Todo; если Todo пуст — задача из In progress без живой сессии. Действия: «Начать» (задача → In progress, новое окно терминала в `projectPath`, иначе в `cwd` текущей сессии) / «Следующая» (показать следующую по порядку) / «Позже».
3. **Обдумать следующий шаг** по задаче текущей сессии (если сессия не привязана — предложить привязать или завести задачу): поле заметки «Что сделаю после этого шага?», сохраняется в `note` задачи. Плюс кнопка «+ задача» — быстро скинуть в Todo то, что пришло в голову.

Действия на любой карточке: «Отложить 5 мин» (скрыть карточки для этой сессии), «Закрыть».
`NextActionEngine` — чистая функция `(SessionsSnapshot, BoardSnapshot, HistoryLookups, now) -> NextAction?`, полностью покрыта unit-тестами.

### F6. Детектор отвлечения
- Активен только когда ≥1 сессии в `running`.
- Источник: `NSWorkspace.didActivateApplicationNotification` + опрос раз в 5 с URL активной вкладки для Safari, Chrome, Arc через AppleScript (требует разрешения Automation; если не выдано — работаем только по приложениям).
- Стоп-лист (настраивается в Settings): по умолчанию приложения `Telegram`, `Discord`; домены `youtube.com`, `x.com`, `twitter.com`, `reddit.com`, `instagram.com`, `tiktok.com`, `news.ycombinator.com`, `vc.ru`, `habr.com`.
- Срабатывание: непрерывно в стоп-листе ≥ `distractionThreshold` (по умолчанию 20 с) → nudge-карточка: текущая задача, ждущие сессии, следующая задача из Todo, кнопки «Вернуться» (jump к последней активной сессии) и «Мне это нужно (10 мин)» (подавить детектор на 10 минут).
- Повторный nudge не раньше чем через 3 мин в том же эпизоде.
- Логируется `DistractionEpisode`: `startedAt`, `endedAt`, `appBundleId`, `domain?`, `nudged`, `returnedWithinSec?`.

### F7. Статистика
- Вкладка «Статистика» в окне доски: за сегодня и за 7 дней — задач закрыто, сессий запущено, доля сессий с привязкой к задаче, эпизоды отвлечения и суммарное время, медианное время реакции на «Что дальше?».

### F8. Настройки
- Задержка F5, порог F6, стоп-лист, терминал для Resume, хоткей доски, вкл/выкл F5/F6, звук nudge (по умолчанию выкл).

## 6. Нефункциональные требования
- Local-first: никаких сетевых запросов (Sparkle в форке выключен).
- Хуки fail-open (наследуется): если приложение не запущено, Claude работает как обычно.
- Хук не добавляет видимой задержки к Claude: обработка в приложении асинхронная, ответ хуку сразу (кроме permission).
- Drag & drop на доске до 300 задач — без заметных лагов.
- Backfill истории для ~5 000 jsonl-файлов — в фоне, не блокирует UI, < 60 с.
- Потребление CPU в простое < 1%.
- Данные: `~/Library/Application Support/Focus/focus.sqlite` (история сессий, задачи, эпизоды отвлечений).

## 7. Архитектура

### 7.1 Что берём из апстрима
`OpenIslandCore` (BridgeServer, BridgeTransport, ClaudeHooks, ClaudeHookInstaller, SessionState, ClaudeTranscriptDiscovery, AgentSession), `OpenIslandHooks` (CLI хука), `OpenIslandApp` (NotchPanel, OverlayPanelController, IslandPanelView, TerminalJumpService, Settings).

### 7.2 Что вырезаем
Codex (вкл. app-server), Gemini, Cursor, OpenCode, Pi, Kimi, Grok, Qoder/Qwen/Factory/CodeBuddy/Droid, iOS/Watch companion + `WatchHTTPEndpoint`, SSH-remote Python-хук, Sparkle, i18n zh-Hans/zh-Hant (строки апстрима остаются en; новые Focus-экраны — на русском). `AgentTool` сводится к одному кейсу или удаляется; ветвления в `BridgeServer`, `AgentSession`, `HookInstallationCoordinator`, `SettingsView` упрощаются.

Порядок: сначала вырезание с зелёными `swift build` / `swift test`, затем Focus-модули.

### 7.3 Новые модули
Новый SPM-таргет `FocusCore` (без AppKit, тестируемый):

| Компонент | Ответственность |
|---|---|
| `FocusStore` | SQLite (GRDB): таблицы `sessions`, `tasks`, `distraction_episodes`, миграции |
| `SessionHistory` | upsert записей из событий `SessionState`, backfill из jsonl (переиспользует парсер `ClaudeTranscriptDiscovery` без лимита 24 ч), поиск |
| `BoardService` | CRUD задач, перемещение между колонками и переупорядочивание (`position` — дробный ключ, без перенумерации), авто-переезд в In progress при привязке, выбор «текущей задачи» |
| `NextActionEngine` | чистая функция выбора карточки (F5) |
| `TurnTracker` | по потоку событий определяет «сессия ушла в работу» и ведёт таймер задержки |
| `DistractionClassifier` | чистая функция `(appBundleId, url?, stopList) -> Bool` |

В `OpenIslandApp`:

| Компонент | Ответственность |
|---|---|
| `FocusCoordinator` | подписка на изменения `AppModel`/`SessionState` → `SessionHistory`, `BoardService`, `TurnTracker`, `NextActionEngine`; показ карточек через `OverlayUICoordinator` |
| `FrontmostAppMonitor` | NSWorkspace + AppleScript-опрос URL → `DistractionClassifier` → эпизоды и nudge |
| `ResumeLauncher` | открыть терминал с `claude --resume` или пустой `claude` в папке проекта (AppleScript для Terminal/iTerm, CLI для Ghostty) |
| `BoardWindowController` | окно доски, глобальный хоткей |
| Views | `BoardView` (колонки, drag & drop), `TaskDetailView`, `CurrentTaskBadge` (свёрнутый island), `IslandTasksTab`, `TaskBindingChip`, `NextActionCard`, `DistractionNudgeView`, `HistoryView`, `StatsView` |

Инвариант апстрима сохраняется: `SessionState.apply` — единственное место изменения живых сессий. Focus-модули только читают снапшоты и пишут в собственное хранилище.

### 7.4 Поток данных
```
claude hook → OpenIslandHooks → bridge.sock → BridgeServer → SessionState
                                                         │
                                                         ▼
                                              FocusCoordinator ──► SessionHistory / BoardService ─► focus.sqlite
                                                 │      │
                                     TurnTracker ┘      └ FrontmostAppMonitor
                                          │                       │
                                          ▼                       ▼
                                   NextActionEngine        DistractionClassifier
                                          └──────► Island UI ◄────┘
                                                      │
                                                 BoardWindow
```

## 8. Обработка ошибок
- Сокет недоступен → хук fail-open (как в апстриме), история догоняется через backfill jsonl при следующем старте.
- Нет Automation-разрешения для браузеров → F6 работает только по приложениям, в Settings — предупреждение с кнопкой «Выдать».
- Битый/частично записанный jsonl → строка пропускается, файл не помечается обработанным до следующего mtime.
- Ошибка миграции SQLite → бэкап файла в `focus.sqlite.bak-<ts>`, создание новой БД, баннер в Settings.
- Удаление задачи с привязанными сессиями → у сессий `taskId` обнуляется, сами записи истории остаются.
- Resume: `claude` не найден в PATH терминала → терминал покажет ошибку; island заранее не проверяет.

## 9. Тестирование
- Unit (XCTest, `FocusCoreTests`): `NextActionEngine` (все ветки приоритета, анти-спам), `TurnTracker` (последовательности событий), `DistractionClassifier` (домены/поддомены), `BoardService` (перемещения, порядок, авто-переезд при привязке, выбор текущей задачи), `SessionHistory` (upsert, backfill из фикстур jsonl).
- Сохраняем и чиним существующие тесты апстрима после вырезания агентов.
- Ручной smoke: две параллельные сессии `claude`, проверка S1–S6.

## 10. Метрики успеха (собираются локально, видны в F7)
- Медианное время от «Claude ушёл в работу» до следующего действия пользователя (клик по карточке/jump) — цель < 30 с.
- Эпизоды отвлечения в день и суммарное время — цель: снижение на 50% за 2 недели относительно первой недели.
- Доля сессий, привязанных к задаче, — цель ≥ 70% (работа идёт по доске).

## 11. Вне скоупа MVP (v2+)
- LLM-подсказки «что сделать» через `claude -p --model haiku`.
- Произвольные колонки, несколько досок, метки, дедлайны, чеклисты в задаче.
- Синхронизация доски с ClickUp / Trello / Obsidian.
- Запуск `claude` из задачи с её описанием как первым промптом.
- Жёсткий режим (затемнение отвлекающих окон).
- Другие агенты, мобильный компаньон, синхронизация между машинами.

## 12. Открытые риски
- Апстрим активно развивается; после урезания мерж апстрима станет дорогим — принимаем, форк живёт самостоятельно.
- Определение «пользователь открыл completed-сессию» опирается на фокус терминала — для некоторых терминалов (Warp, IDE) может быть неточным.
- AppleScript-опрос браузеров может вызывать системные промпты при первом запуске.
- Drag & drop в SwiftUI на macOS 14 имеет ограничения при переупорядочивании внутри списка — может потребоваться NSViewRepresentable-обёртка.
